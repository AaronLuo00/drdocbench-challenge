Evaluation

Evaluation Framework

Submissions are evaluated under scoring contract drdocbench-document-parsing-v3-single-page-md2md. Every submitted page is compared only with its matching hidden per-page reference Markdown, and reference and prediction Markdown follow the same parsing and matching path. Each available component is converted to a higher-is-better 0-100 score before page-level aggregation.

Document Parsing metrics
Text Edit Distance
Normalized Levenshtein distance over scored text elements, 0-1; lower is better.
Table TEDS
Mean similarity over valid table samples, displayed on 0-100; higher is better.
Formula CDM
Mean CDM F1 over isolated display formulas, displayed on 0-100; higher is better.
Reading Order
(1 - normalized reading-order edit distance) * 100; higher is better.
Overall
Mean of the per-page available-component averages; higher is better.
Overall formula: for each page, average only its available Text, Table, Formula, and Reading Order scores; then average the scorable page scores. Missing components are excluded, not assigned zero.

Scorable-page audit. Public Validation v3 requires 1,005 page predictions: 962 are scorable and 43 are non-scorable. Private Test v3 requires 509 page predictions: 488 are scorable and 21 are non-scorable. A non-scorable page contains no Text, Table, Formula, or Reading Order component after its reference Markdown is parsed and is excluded from every metric denominator.

Submission

Submission Format

Participants upload one ZIP containing exactly one Markdown prediction for every manifest-defined page.

Recommended Markdown layout

Mirror the source mds/ hierarchy exactly and keep one file per page. Do not add a wrapper directory around the subject folders.

submission.zip
└─ CHEMISTRY/
   └─ <document_id>/
      └─ mds/
         └─ <document_id>_1.md

JSONL is also supported. Each line must contain subject, document_id, integer page, and string markdown.

{"subject":"CHEMISTRY","document_id":"...","page":1,"markdown":"Text\n\n$$E = mc^2$$"}
Formula delimiters: the evaluator accepts $ ... $ or \( ... \) inline, and $$ ... $$ or \[ ... \] for display formulas. Structured HTML table contents are preserved as submitted and compared by TEDS.

Release checklist

  • Ready Exact phase page manifest
  • Ready Full structurally valid sample ZIP
  • Ready Standalone archive validator
  • Ready SHA-256 checksums

FAQ

Frequently Asked Questions

Which data should I use for EvalAI?

Use the versioned Validation or Test participant package linked on this page. The labeled Hugging Face benchmark is a reference release, not a phase input package.

Where will submissions be evaluated?

Submissions are evaluated by the remote Dr.DocBench worker through EvalAI challenge 2717.

How is Overall computed?

Each page averages its available 0-100 component scores. Overall is the mean over scorable pages. Missing components are excluded from the denominator. Public Validation has 43 non-scorable pages and Private Test has 21; those pages remain required when their input image is released but do not affect scores.

What must top-ranked teams provide?

A technical report is required, and all external data must be disclosed.
