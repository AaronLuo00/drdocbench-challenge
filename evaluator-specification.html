Scoring contract

Dr.DocBench Document Parsing Evaluator

drdocbench-document-parsing-v2-md2md

Prediction unit

Every manifest identifier (subject, document_id, start_page, end_page) must occur exactly once. Missing, extra, or duplicate windows fail structural validation.

Ground-truth source

The production reference is the curated per-page Markdown in mds/*.md. For every required window, the evaluator reads the covered page files in ascending order, strips outer whitespace, and joins them with one blank line. The merged reference and submitted Markdown are parsed and matched through the same evaluation path. Private structured annotations are retained for auditing and regression diagnostics.

Metrics

  • Text ED: normalized Levenshtein distance over scored text categories, 0-1; lower is better.
  • Table TEDS: mean valid-table similarity, displayed on 0-100; higher is better.
  • Formula CDM: mean isolated-formula CDM F1, displayed on 0-100; higher is better.
  • Reading Order: (1 - normalized edit distance) * 100; higher is better.

Overall

WindowOverall(w) = mean(available 0-100 components in w)
Overall          = mean(WindowOverall(w) for every scorable window w)

Unavailable components are excluded, not assigned zero. Windows with no supported component are excluded from every metric denominator.

Phase manifest audit

  • Public Validation v1: 67 documents, 1,005 pages, and 938 required identifiers; 919 are scorable and 19 are non-scorable.
  • Private Test v2: 34 held-out documents, 509 released pages, and 474 required identifiers; 473 are scorable and one is non-scorable.

A non-scorable window contains no Text, Table, Formula, or Reading Order component after its reference Markdown is parsed. It is required for structural completeness but does not affect any score. Private Test v2 also excludes one empty reference page for which no input image was provided, and no window crosses that page-number gap.

Formula syntax

The Markdown parser accepts $ ... $ or \( ... \) inline, and $$ ... $$ or \[ ... \] for display formulas. The current GT primarily uses dollar delimiters in text and Pandoc-style \( ... \) spans inside some structured HTML tables. Table cell contents are preserved as submitted and compared by TEDS.
