Scoring contract

Dr.DocBench Document Parsing Evaluator

drdocbench-document-parsing-v1

Prediction unit

Every manifest identifier (subject, document_id, start_page, end_page) must occur exactly once. Missing, extra, or duplicate windows fail structural validation.

Metrics

  • Text ED: normalized Levenshtein distance over scored text categories, 0-1; lower is better.
  • Table TEDS: mean valid-table similarity, displayed on 0-100; higher is better.
  • Formula CDM: mean isolated-formula CDM F1, displayed on 0-100; higher is better.
  • Reading Order: (1 - normalized edit distance) * 100; higher is better.

Overall

WindowOverall(w) = mean(available 0-100 components in w)
Overall          = mean(WindowOverall(w) for every scorable window w)

Unavailable components are excluded, not assigned zero. Windows with no supported component are excluded from every metric denominator.

938 required, 900 scored

The current manifest contains 938 required identifiers. Exactly 900 have at least one supported Text, Table, Formula, or Reading Order component. The other 38 contain only figures, figure captions, masks, figure footnotes, page numbers, or no layout detections. They are required for structural completeness but do not affect any score.

Formula syntax

The canonical syntax follows the GT: $ ... $ inline and $$ ... $$ display. Before scoring, the evaluator normalizes accepted \( ... \) and \[ ... \] compatibility delimiters to the canonical form. Unit tests require both representations to materialize identically.
